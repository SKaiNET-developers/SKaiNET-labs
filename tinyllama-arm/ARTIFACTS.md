# Reusable artifacts

Everything below exists because this project needed it, but none of it is specific to this
project. One row per artifact: what it is, who it helps, how to run it.

| Artifact | What it is | Who it helps | Run it with |
|---|---|---|---|
| **KleidiAI yardstick harness** | [`benchmarks/kleidiai/`](benchmarks/kleidiai/) — a single-file C harness that benchmarks *your* quantized matmul kernel against Arm's KleidiAI micro-kernels at real TinyLlama decode shapes, with fair rules (packing outside the timed loop on both sides, activation quant timed on both sides, ≥96 MB rotating working set) | Anyone writing Arm CPU kernels who wants an honest "how far from Arm's own assembly am I?" number in ~90 s, no model download | The `cc` one-liner in [`benchmarks/kleidiai/README.md`](benchmarks/kleidiai/README.md) on any AArch64+dotprod machine |
| **Five Neon GGUF-format kernels** | Hand-written C kernels for Q8_0, Q4_K, Q5_K, Q6_K (and, upstreamed during this project, Q4_0) that consume ggml packed blocks in place — no dequant-to-FP32 pass | Any runtime that wants to run GGUF weights on Arm without a llama.cpp dependency | Shipped in `sk.ainet:skainet-backend-native-cpu` since 0.36.0; sources in the [SKaiNET repo](https://github.com/SKaiNET-developers/SKaiNET) under `skainet-backends/skainet-backend-native-cpu/native/src/` |
| **Kernel provider SPI** | Priority-ranked kernel registry (scalar reference 0 / JVM Panama SIMD 50 / native Neon 100) with per-format nullable accessors — a missing kernel degrades to the next tier instead of failing | Anyone building a multi-backend numeric runtime on Kotlin | Automatic in any SKaiNET ≥0.36 consumer; provider selection is logged at startup |
| **`PhaseProfile` + `KernelProfile`** | Named-bucket timing that splits a decode step into matmul vs non-matmul phases (attention, norms, logits, detok, alloc) — the instrument that attributed the board gap to ~46% matmul / ~54% runtime tail | Anyone whose kernel wins stopped moving end-to-end numbers | `SKAINET_PROFILE=1` before any run in this repo |
| **The perf-log protocol** | One improvement = one annotated git tag + one logbook entry (mechanism + reproduction command) + one CSV row; negative results get logged too | Anyone who has ever lost a benchmark number | [`scripts/perf-log.sh`](scripts/perf-log.sh); ledger in [`docs/perf-history.csv`](docs/perf-history.csv); method in [`docs/PERF-LOGBOOK.md`](docs/PERF-LOGBOOK.md) |
| **GGUF → StableHLO → IREE runbook** | The complete compiled-path recipe: int8 quantization to fit a 2 GB budget (4.2 GB FP32 → 1.1 GB `.irpa`), aarch64 compile, on-device run — including the trap where a 3.11-compiled vmfb is rejected by a 3.10 runtime with only `requires [Ch]` as the clue | Anyone taking an ML graph to an embedded Arm target through IREE | [`scripts/build-iree-int8.sh`](scripts/build-iree-int8.sh), [`scripts/decode-board.sh`](scripts/decode-board.sh) |
| **SL2619 / Yocto bring-up notes** | The board facts that cost days to learn: `/tmp` is tmpfs and eats RAM, the `libcrypt.so.1` shim, protecting `adbd` from the OOM killer with `oom_score_adj` before memory-heavy runs | Anyone deploying to a small-RAM Yocto Arm board over adb | Read [`docs/BOARD_SL2619.md`](docs/BOARD_SL2619.md) |
| **KleidiAI buy-vs-build evaluation** | The written decision: why we benchmarked Arm's kernels, lost 1.95×, and still did not vendor them (format fidelity: per-32 asymmetric minima vs `qsi4c32`'s symmetric quantization; no Q6_K equivalent) | Anyone facing an adopt-or-compete decision against a vendor library | Read [`docs/KLEIDIAI-EVALUATION.md`](docs/KLEIDIAI-EVALUATION.md) |
| **Negative results** | The int-dot rewrite that changed matmul time by exactly 0 ms, the cache-locality reorder that won 2.07× on Q4_K and nothing on Q6_K (dequant-bound, not locality-bound), and the KleidiAI decision above | Anyone about to repeat one of these | Logged inline in [`docs/PERF-LOGBOOK.md`](docs/PERF-LOGBOOK.md) — search "no win" |
